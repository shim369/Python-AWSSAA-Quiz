# 本番形式の問題の作問ルール

本番形式の問題(`data/exam_questions/*.yaml`)を作るときのルールです。
人が書くとき、Claude Code の skill(`.claude/skills/exam-questions/`)で作るとき、
Claude API のスクリプト(`scripts/draft_exam_questions.py`)で作るときの、どれでも同じルールを使います
(スクリプトはこのファイルをそのままプロンプトに入れます)。

## 形式(本番の試験ガイドと同じ)

- 単一選択: 正解1つ+誤答3つの4択
- 複数選択: 5択で正解2つ(全体の2割程度)。問題文に「2つ選択」とは書かない(アプリが表示する)
- 問題文は2〜4文のシナリオ: 会社の状況 → 要件・制約 → 問い
- 問いには、本番でよく使われる判断基準を1つ入れる
  (例: 「最もコスト効率が高い」「運用上の負荷が最も少ない」「最小限の変更で」「最も高い可用性」)

## 選択肢の作り方

- 誤答は「知識が不十分な受験者が選びそうな、もっともらしい案」にする。
  実在する機能の組み合わせで、動作はするが要件か判断基準のどれかを満たさない案がよい
  (コストが高い、運用負荷が大きい、可用性が足りない、要件の一部しか満たさない など)
- 存在しない機能や、明らかに無関係なサービスを誤答にしない
- 正解の選択肢だけが長い・詳しい、といった見た目の手がかりを作らない
- 問題文に正解のサービス名をそのまま書かない
- 各選択肢の reason には、正解なら決め手、誤答ならどの要件を満たさないかを1〜2文で書く
- explanation には、この問題で覚えるべき判断のポイントを2〜3文で書く

## 正確さ

- AWSの現在の仕様に沿って書く。自信のない仕様(料金の細かい数値、上限値など)を問題の根拠にしない
- 実際の試験問題、問題集、ブレインダンプの問題を再現・翻案しない。必ずオリジナルのシナリオにする

## 出題範囲

- 試験ガイドのタスク(`src/python_awssaa_quiz/exam_guide.py` の `TASKS`)ごとに、そのタスクの観点(focus)から出題する
- 同じタスクの既存の問題と、同じシナリオ・同じ正解の組み合わせにならないようにする
- related_keywords には、キーワード集(`data/AWS_SAA_重要キーワード集.xlsx`)の No から、問題に関係するものを2〜5個選ぶ
